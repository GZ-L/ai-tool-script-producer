# 02 Script Structure

Use this file while drafting the口播稿.

## Default 30-45 Second Structure

| Time | Job | Required Content |
|---|---|---|
| 0-3s | One-core-result project sentence | "这是一个能帮你【一个核心结果】的【项目/工具/网站】" |
| 3-9s | Pain scene | The specific workflow pain or information overload this tool solves |
| 9-13s | Name the tool | Tool name, correct spelling/pronunciation if needed |
| 13-16s | Add achievement | Verified star count, backing, milestone, release, rating, or positioning fallback |
| 16-28s | Core capabilities | 2-3 concrete things it does, ideally "第一/第二/第三" |
| 28-38s | Usage paths | Ordinary-user path, Agent/user path, developer/self-host path when relevant |
| 38-45s | Elevated positioning + CTA | "它不是...更像是..." plus who should save it |

The first sentence is mandatory and must contain only one core result. It should make the project instantly understandable, not complete. The achievement sentence is also mandatory and must appear immediately after the tool name. If no proof is verified, use a positioning fallback and mark that no public achievement was confirmed.

## Script Formula

```text
这是一个能帮你【一个核心结果】的【开源项目/工具/网站】。

如果你每天都在【具体痛苦场景】，
最麻烦的不是【表层问题】，而是【真正问题】。

这个工具叫【工具名】。
【战绩/成就句】。

它会帮你做三件事：
第一，【能力1】。
第二，【能力2】。
第三，【能力3】。

普通用户【怎么用】。
如果你想让 Agent 帮你【做什么】，也可以【Agent路径】。
如果你想做自己的【高阶版本】，还可以【开发者/自建路径】。

所以它不是【普通定位】，更像是【升维定位】。
做【目标人群1】、【目标人群2】、【目标人群3】的人，可以先收藏这个项目。
```

## First Sentence Rule

Use a direct project one-liner, not a generic hook.

Hard rule:

```text
这是一个能帮你【一个核心结果】的【开源项目/工具/网站】。
```

The first sentence must not include:

- A second capability.
- Mechanism explanation.
- Advanced positioning.
- A comma clause.
- `并且`, `以及`, `同时`, or similar expansion words.

Good:

```text
这是一个能帮你自动盯 AI 圈动态的开源项目。
这是一个能把 PDF 翻译成双语对照版的开源工具。
这是一个能把一条视频反推出完整提示词的网站。
```

Avoid:

```text
如果你每天都在刷很多 AI 新闻...
做 AI 内容的人一定要看...
我发现了一个很强的工具...
这是一个能帮你自动盯 AI 圈动态，并把分散消息整理成故事线的开源项目。
```

Pain scenes can appear in the second sentence, after the project one-liner.

## Body Rules

- Lead with outcomes, not feature lists.
- Explain use as "what it monitors/accepts -> how it processes -> what it outputs".
- Keep each sentence short enough for subtitles.
- Put install/download/use steps near the end, after the value is clear.
- For GitHub projects, distinguish "online demo", "fork/self-host", and "install Skill/extension" if they are different paths.
- If setup is technical, say who it is for: ordinary users use the hosted page; developers fork or install.
- Use "第一/第二/第三" when the tool has multiple clear capabilities.
- Use an elevated positioning sentence near the end: "所以它不是...更像是..." when it helps clarify the tool's category.

## CTA Options

- Resource CTA: `我把链接和使用步骤放在评论区/简介里。`
- Comment CTA: `你想让我用它追踪哪类 AI 更新？`
- Save CTA: `做 AI 内容选题的人，先收藏备用。`
- Follow CTA: `下期继续拆一个真正能用的 AI 工具。`

Use a resource or save CTA by default. Avoid empty endings like "感兴趣可以了解一下" unless the user asks for a lighter ending.
